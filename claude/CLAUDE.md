## Pre-flight check

Before non-trivial work, `git fetch` and summarize any new commits on this branch's upstream or the default branch that HEAD doesn't have. For issue work, also check open and recently merged MRs/PRs for overlap.

## Language

- Identifiers and branch names: always English.
- Comments, docs, user-facing strings, commits, issues, MRs/PRs (including drafts in replies): use the language the project's CLAUDE.md sets; otherwise match the prevailing language of existing ones of the same kind (surrounding comments, `git log`, recent issues/MRs). Use English if there are none. Never take it from the conversation language.
- Reply in the language I write in, question dialogs included. Identifiers stay as they are.

## Replies

- Be brief: lead with the conclusion or the ask. Add detail only when it changes what someone does, more on request. The same goes for MR and issue comments.
- I sometimes ask without a question mark ("UTM campaign je povinná"). When a short message can be a question or a change request, answer how it works now and offer the change; change things only on a clear request.

## Plan Mode

Write plans and textual content (issue descriptions, specs, MR bodies) directly in the response. Do NOT create plan files unless asked.
